# fund_report_tool 改进路线图

按优先级从高到低排序。标注了每个改进的价值（高/中/低）和实现难度（高/中/低）。

---

## 第一优先级：立即能用（本周可做）

| # | 改进方向 | 价值 | 难度 | 说明 |
|---|---|---|---|---|
| 1 | 测试图表功能 | 高 | 低 | 当前 chatbox 已支持 draw_chart，但还没完整测试。先跑通再迭代 |
| 2 | 一键启动（双击图标） | 高 | 低 | macOS 用 .command 或 Platypus 打包成 .app；Windows 用 .bat |
| 3 | 数据导出（整库备份） | 高 | 低 | 一键把 fund_data.db 导出为 Excel 工作簿，方便审计和备份 |
| 4 | 图表类型扩展 | 中 | 低 | 添加同比柱状图、多指标对比图（营收 vs 成本） |

## 为什么这样排序？

**先做第一优先级的原因：**
- 图表功能和一键启动是已经做了 80% 但还没收尾的工作，做完马上提升使用体验
- 数据导出是最低成本的"保险"，你现在没有任何数据备份手段

**安全为什么排第二：**
- 你处理的是真实投资数据，LLM 外传风险和局域网开放风险是真实存在的
- 但当前只有你一个人用，短期内风险可控

**自动化为什么排第三：**
- 自动抓取财报听起来很酷，但实施复杂度高，且企业发送格式不固定
- 建议先手动跑通流程，再逐步自动化

**协作为什么排最后：**
- 只有你自己在用，多用户体系暂时不需要
- 等真的有同事需要接入时再做，避免过度设计

## 我的建议：先做这 4 个

如果你本周只能做一件事，建议按这个顺序：

1. **测试图表 + 修复 bug**（今天）
2. **一键启动**（明天）
3. **整库数据导出**（本周）
4. **本地 LLM（Ollama）**（下周）

这 4 个做完，系统的可用性和安全性就上了一个台阶，可以安心给同事用了。
